-----ANALYSIS------
How to read the trigger names: The general structure is: L1_ObjectThreshold_ExtraCondition

HLT - High-Level Trigger, the software trigger stage in CMS
Iso - Isolated, meaning little extra particle activity near the muon
HLT_IsoMu24 - Isolated MIuon with approximate transverse momentum threshold, pT ≳ 24 GeV

Invariant mass is one of the most important tools in particle physics because unstable particles are found as peaks in invariant mass histograms.

A differential Drell-Yan cross section tells you how often Drell-Yan events occur as a function of some measured variable, not just the total probability.
-----------

The general structure once again
TTree Events -> Table of CMS collision events
One tree entry -> One collision event
One branch -> One stored quantity, for example Muon_pt, nMuon, HLT_IsoMu24
Branch value at entry i -> Value of that quantity for event i

----NORMALIZATION PRACTICE:
normtag_PHYSICS_pp_2016.json CMS had several luminosity-measurement systems. The normtag selects the preferred calibrated luminometer for each luminosity section. The official 2016 luminosity record states that the best luminometer for each section is recorded in this normtag. The normtag therefore tells brilcalc which calibration source to use, while the certification JSON tells it which sections are acceptable.

curl.exe -L "https://opendata.cern.ch/record/1059/files/normtag_PHYSICS_pp_2016.json" -o normtag_PHYSICS_pp_2016.json

We ran the CMS brilcalc tool in the official Docker container:The CMS guide recommends using brilcalc --byls --output-style csv when luminosity values are needed separately for each luminosity section

docker run --rm -v "${PWD}:/work" -w /work gitlab-registry.cern.ch/cms-cloud/brilws-docker bash -lc "brilcalc lumi -c web --byls --output-style csv --begin 281613 --end 284044 -i /work/Cert_271036-284044_13TeV_Legacy2016_Collisions16_JSON_MuonPhys.txt --normtag /work/normtag_PHYSICS_pp_2016.json -u /fb > /work/Run2016H_MuonPhys_lumibyls.csv"

This produces a machine-readable comma-separated table that the C++ code can parse. Therefore, the CSV does not contain arbitrary data-taking sections. It contains sections allowed by the certification selection.
