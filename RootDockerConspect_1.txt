Branches = columns (but not detectors)
A branch is: stored variable or reconstructed quantity and not a detector channel.
The CMS detector actually contains millions of readout channels.
Detector subsystem: Silicon tracker(~75 million), ECAL(~76 thousand crystals), HCAL(thousands of channels), Muon chambers(hundreds of thousands)...
Instead, NanoAOD format stores processed high-level physics quantities.
The real chain is: proton-proton collision  -> detector signals  -> digitization  -> reconstruction algorithms  -> physics objects  -> NanoAOD branches
Why there are so many branches? Because CMS stores many kinds of information.

A RUN is a long continuous data-taking period. A run may last from minutes to hours. So run tells: "Under which detector/accelerator conditions was this event recorded".
LUMINOSITYBLOCK Inside a run, CMS divides time into smaller chunks called luminosity blocks. A luminosity block is roughly: ~23 seconds of data-taking. So luminosity blocks help with: Data quality monitoring(to reject bad periods), Luminosity calculations(to integrated luminosity accounting), Trigger monitoring(trigger-rate studies), Bookkeeping(detector status tracking)
EVENT This is the actual collision-event number. Each proton-proton collision event gets a unique event identifier inside the run/luminosity-block structure.
So: (run, luminosityBlock, event)
Run

 │     ├── Event
 │     ├── Event
 │     ├── Event
 │     └── ...
 ├── Luminosity block
